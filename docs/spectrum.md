# Simulated spectrum measurements

I wanted to learn what a spectrum analyzer reports before using a real one. This exercise uses a local simulated instrument, not hardware or measured data. My hands-on waveform work is from NE 241 labs.

Run `uv run python -m lab_assay.spectrum --output spectrum-output`. The folder contains `spectrum.png` and `report.json`. For example, change the source and filter with `--source-frequency-hz 2500000 --source-power-dbm -20 --rbw-hz 200000`; set the sweep with `--start-hz` and `--stop-hz`, and the spur threshold with `--spur-limit-dbc`. Frequencies and bandwidth are in Hz; power is in dBm (decibels relative to one milliwatt). The limit is in dBc, relative to the main peak. A more negative spur is weaker.

The client sends SCPI text commands through a PyVISA socket to a local simulator. It configures the source, sweep and resolution bandwidth (RBW), starts a sweep, checks the instrument error queue and reads 2,001 points. The simulator adds a fundamental, second and third harmonics and one spur to a flat -120 dBm/Hz noise density in linear power. Gaussian filter shapes have a full width at half maximum equal to the RBW; the integrated noise rises by 10 log10(RBW). This is an illustrative model, not a calibrated analyzer or a sampled waveform.

The strongest bin is the fundamental. The median trace is a simple noise floor estimate, which assumes most bins contain noise. The largest bin within one RBW of each integer multiple is reported as a harmonic; an incomplete search window is marked outside the sweep. The strongest local maximum outside the fundamental and harmonic windows is compared with the spur limit. If there is no local maximum, the spur result is unknown rather than a pass. A harmonic below the noise floor is not distinguishable from noise in this simple search. The RBW must span at least two trace intervals. Real measurements need calibrated equipment, appropriate detector and filter settings, and uncertainty and noise corrections.
