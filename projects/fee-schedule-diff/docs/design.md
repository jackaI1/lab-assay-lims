# Extraction and comparison boundaries

The extractor reads one PDF page at a time with pdfplumber, groups words by vertical position, and looks for a five-digit code at the left of a fee-table row. Letter prefixes are preserved separately, with the five digits used as the comparison key. Leading zeros remain strings. Word coordinates are measured in PDF points and tuned for the public MSC layouts used here. Character and layout caches are released after each page.

A confident fixed-price row needs a description, table leader dots and one monetary value in the fee column. Notes are kept in raw evidence but excluded from descriptions. Values in the separate anesthesia-level column are not prices. Dollar amounts are stored as strings and compared with Decimal, which avoids binary floating-point rounding. Only whitespace and leader dots are normalized, so punctuation and capitalization can count as wording changes.

Asterisk-qualified codes, missing fees, multiple prices, percentage-based prices, missing leader dots and conflicting duplicate codes go to review. A percent sign in a service description, such as a body-surface-area unit, is not automatically a percentage-based price. Blank or image-only pages also get a page-level review entry. A wholly unsupported or image-only document fails extraction rather than silently producing an empty comparison. There is no OCR, meaning conversion of image text into searchable text.

Identical repeated code rows are consolidated with all occurrence pages retained. Conflicting repetitions are quarantined, meaning excluded until checked. A code with any unresolved occurrence in either edition is excluded from both sides of the comparison. This includes unpriced reference lists, even when another occurrence has a price. This conservative rule sacrifices coverage to avoid turning an extraction failure into a false addition or removal. No manual overrides are hidden in the example.

For each resolved code, the comparator checks presence, price, description and letter prefix. One code can have several change categories. The JSON includes both source rows, original text blocks, edition labels, page URLs, source checksums, counts and the complete review queue. Markdown is generated from the same object. The short report is a preview; the full report contains every reported change.

The physical PDF page is one-based and linked with `#page=...`. It may differ from the section number printed in the footer, and some browser PDF viewers ignore page fragments. Removed codes link to the old edition, added codes to the new edition, and changed rows to both.

These are document differences, not a billing engine. Notes, preambles, section headings, eligibility rules, anesthesia values and unrecognized layouts are not compared. A source can contain an unrecognized fee row that never becomes a candidate. Consequently, an “added” or “removed” label means a difference in the resolved fixed-price extraction and needs source review before being treated as an official fee-code addition or deletion.

The fetch command downloads source PDFs into an ignored cache. Exact copies of the successful original downloads are retained in `data/snapshots/` so report reproduction works when the provincial site is unavailable from a CI runner. `data/sources.json` pins their SHA-256 hashes, fingerprints of their exact bytes. A changed download is rejected rather than overwriting the cache. The repository retains those original snapshots, derived reports and small public page-text fixtures. The PDFs belong to the Province of British Columbia; links identify the original publication. There are no patient records, claims, private-system connections or substituted sources.
